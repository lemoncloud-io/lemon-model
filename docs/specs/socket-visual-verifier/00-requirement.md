# Requirement: socket-visual-verifier

**Status:** Confirmed
**Date:** 2026-07-10
**Slug:** socket-visual-verifier

## 키 / 컨셉

lemon-model `src/socket`이 약속하는 전송 계약을 로컬 브라우저에서 눈으로 확인하는 시각 검증 도구다.

## 해결하려는 문제

- 청크 분할·재조립, send→result 매칭 같은 동작이 vitest로만 검증되고, 실제 왕복을 눈으로 볼 방법이 없다.
- in-memory 테스트는 있지만 실제 WebSocket 전송 경로를 거치는 왕복은 검증된 적이 없다.
- 지연·지터·순서섞임 같은 악조건에서 전송 계약이 유지되는지 확인할 수단이 없다.
- 패킷 유실·변조 같은 결함이 생겼을 때 그것이 어떻게 드러나는지 확인할 수단이 없다.
- 추후 실서버(WSS API)에 붙이기 전에 클라이언트 동작을 미리 검증할 중간 단계가 없다.

## 요구사항

- 두 peer 사이의 기본 왕복 교환(send→result 상관, ping→pong)을 확인할 수 있다.
- 패킷 크기 한계를 넘는 메시지가 분할·재조립되는 과정을 확인할 수 있다.
- 연결·핸드셰이크·종료·재연결·에러 다섯 가지 수명주기 이벤트를 각각 확인할 수 있다.
- 지연·지터·순서섞임을 걸어도 위 동작들이 깨지지 않음을 확인할 수 있다.
- 패킷 유실·변조를 주입하면 재조립 실패·에러가 정상 흐름과 구분되어 타임라인에 드러남을 확인할 수 있다.
- 재조립이 완료되지 않은 메시지는 대기 중·타임아웃 상태로 표시되어 실패로 식별된다.
- in-memory 경로만이 아니라 실제 WebSocket 전송을 거친 왕복도 검증할 수 있다.
- 화면에서 메시지 전송·연결 닫기/재연결·조건 조절을 즉석에서 할 수 있다.
- 모든 이벤트가 시간순 타임라인으로 보이고, 어느 연결의 이벤트인지 구분된다.
- 조건 값을 숫자로 지정하고, 같은 값을 다시 지정해 같은 설정을 반복 재현할 수 있다.

## 목표

- 요구사항의 검증 대상(기본 왕복·청크·수명주기·악조건 강건성·결함 탐지)을 모두 브라우저 타임라인에서 눈으로 확인한다.
- 전송 계약이 깨지는 순간(응답 누락·재조립 실패·에러)이 정상 흐름과 구분되어 보인다.
- socket 모듈을 모르는 개발자가 문서만 보고 스스로 실행과 검증까지 도달한다.
- `src/socket` 코드를 고친 뒤 같은 시나리오를 다시 돌려 회귀 여부를 확인한다.

## 비목표

- 클라이언트당 다중 연결(듀얼소켓) 검증은 다음 버전으로 미룬다.
- 실서버(WSS API) 연동 검증은 제외하고 로컬 실행으로 한정한다.
- CI·vitest 같은 자동화 테스트를 대체하지 않는다.
- 패킷 유실·변조로부터의 복구(재전송·ACK)는 검증하지 않는다 — 결함이 드러나는 것까지만 다룬다.
- 확률적 조건의 이벤트 시퀀스 수준 재현(시드 고정)은 요구하지 않는다 — 설정값 재현까지만 보장한다.
