# Requirement: reliable-chunk-transport

**Status:** Confirmed
**Date:** 2026-07-13
**Slug:** reliable-chunk-transport

## 키 / 컨셉

- 저수준 웹소켓 네트워크 위에서 메시지의 도착을 보장하는 신뢰 전송 계층이다. 
- 큰 데이터는 청크로 나눠 보내고, 유실을 감지·복구해 수신측에 완성본만 전달한다.

## 해결하려는 문제

- 지금의 전송 계층은 보낸 데이터가 상대에게 다 도착했는지 알 길이 없다. 중간이 유실돼도 양쪽 모두 눈치채지 못한다.
- 큰 데이터를 청크로 나눠 보내면 중간 청크 하나만 빠져도 전체를 못 쓰게 된다. 지금은 이를 감지하거나 되살릴 수단이 없다.
- 유실이 조용히 지나가면 불완전한 데이터가 성공한 전송처럼 보인다. 빅파일 전송을 도입하기 전에 이 기반부터 갖춰 둔다.

## 요구사항

- 이 계층을 통과하는 모든 메시지가 도착 보장 대상이다. 
- 큰 데이터는 청크로 나눠 보내며, 청크에 실린 페이로드 종류와 무관하게 같은 보장을 적용한다.
- 수신자는 청크 누락을 스스로 감지할 수 있다.
- 누락된 데이터는 복구된다. 복구 방식(누락분만 재요청, 전체 재전송 w/ ACK 등)은 고정하지 않으며, 어느 방식이든 아래 보장을 만족하면 된다.
- 수신 상위에는 완성본만 전달된다. 불완전한 데이터가 성공처럼 올라가는 일은 없다.
- 같은 전송 단위의 완성본이 두 번 전달되지 않는다. 재전송으로 생긴 중복은 계층이 흡수한다.
- 복구가 불가능하다고 판정되면 해당 전송 단위로 실패를 상위에 알린다. 조용한 손상도, 무한 대기도 없다.
- 송신자와 수신자 모두 이 계층을 사용하는 것을 전제한다.
- 기능은 옵트인이다. 이 계층을 쓰지 않는 기존 사용자 코드는 수정 없이 그대로 동작한다.

## 목표

- 청크 일부를 강제로 떨어뜨려도 수신측이 완성본을 온전히 조립한다.
- 복구가 불가능한 상황에서 실패 통지가 상위에 도착한다.
- 이 기능을 쓰지 않는 기존 사용자의 코드가 수정 없이 그대로 동작한다.
- demo/socket-verifier에서 유실 주입 후 복구, 복구 불능 시 실패 통지를 육안으로 확인할 수 있다.
- src/socket 하위 jest spec으로 위 보장이 회귀 가드된다.

## 비목표

- 모델 동기화 경로에는 적용하지 않는다. 동기화는 마지막 스냅샷만 중요하므로 중간 유실의 복구가 필요 없다.
- 청크 페이로드의 압축·암호화는 다루지 않는다.
- 전송 진행률 UI·콜백은 다루지 않는다.
- dual-socket-network(이중 연결)와의 결합은 다루지 않는다.
- 여러 전송을 동시에 흘릴 때의 대역 배분·우선순위 최적화는 다루지 않는다.
