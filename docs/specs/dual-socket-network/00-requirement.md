# Requirement: dual-socket-network

**Status:** Confirmed
**Date:** 2026-07-12
**Slug:** dual-socket-network

## 키 / 컨셉

- 하나의 클라이언트가 WebSocket 여러 개(첫 번째가 메인, 나머지는 백업)를 동시에 열어 두고, 원할 때 같은 메시지를 연결된 전부로 보낼 수 있게 하는 저수준 다중 연결 지원이다. 기본 시나리오는 2개(1st 메인·2nd 백업)다.

## 해결하려는 문제

- 소켓 하나에만 의존하면 그 연결의 품질이 곧 서비스 품질이 된다. 연결이 불안정해지는 순간 송수신이 함께 흔들린다.
- 중요한 메시지를 한 경로로만 보내면 그 경로의 지연이 그대로 체감 지연이 된다. 두 경로로 보내고 먼저 도착한 쪽을 쓰면 지연을 줄일 수 있다.
- 지금의 lemon-model에는 소켓 여러 개를 묶어 다루는 저수준 수단이 없어, 이중화가 필요한 소비자가 각자 임시로 구현해야 한다.

## 요구사항

- 클라이언트는 소켓 두 개 이상을 동시에 연결해 둘 수 있다. 각 소켓의 대상 URL은 따로 지정할 수 있고, 같아도 된다.
- 첫 번째 소켓이 메인, 나머지는 백업으로 구분된다. 기본 전송은 메인으로만 나간다.
- 호출자는 원할 때 같은 메시지를 연결된 모든 소켓으로 보낼 수 있다(전체 전송). 이때 수신측에 같은 메시지가 여러 번 도착하는 것은 정상이다.
- 소켓들은 서로 독립이다. 한 소켓의 단절·에러가 다른 소켓의 연결과 송수신에 영향을 주지 않는다.
- 자동 장애 전환은 하지 않는다. 한쪽이 끊어지면 그 사실이 상위로 전파될 뿐, 라이브러리가 임의로 경로를 바꾸지 않는다.
- 전체 전송으로 중복 도착한 메시지를 라이브러리가 대신 걸러내지 않고, 새 식별자를 덧붙이지도 않는다. 사본들은 내용이 같으므로 페이로드에 실린 키로 수신자가 같은 메시지임을 판별한다.
- 단절·에러가 일어났을 때 어느 소켓의 것인지 상위에서 구분할 수 있다.

## 목표

- 전체 전송 중 한 소켓을 강제로 끊어도 나머지 소켓들의 송수신이 끊김 없이 이어진다.
- 전체 전송된 사본들이 같은 식별자를 가져, 수신자가 중복을 판별할 수 있다.
- 단일 소켓만 쓰는 기존 사용자의 코드가 수정 없이 그대로 동작한다(옵트인 기능).
- demo/socket-verifier에서 다중 연결·전체 전송·중복 도착을 육안으로 확인할 수 있다. 소켓을 여러 개 추가해 특정 소켓 단독 송신과 전체 전송을 구분해 시연하고, 각 송수신·에러가 어느 소켓의 것인지 타임라인에서 구분할 수 있다.

## 비목표

- 자동 장애 감지·전환(failover)과 메인 자동 승격 로직은 만들지 않는다.
- 모든 소켓에서 유실된 메시지의 복구(재전송·ACK)는 보장하지 않는다.
- 중복 제거를 라이브러리가 대행하지 않는다. 걸러내기는 소비자 책임이다.
- 경로 간 메시지 순서 재정렬은 보장하지 않는다.
- 메시지 단위의 수신 출처 태깅은 하지 않는다. 출처 구분은 단절·에러 이벤트에 한정한다.
- 서버측 변경은 하지 않는다. 클라이언트 라이브러리(src/socket) 범위로 한정한다.
